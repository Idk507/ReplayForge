## Project description draft

Software agents should not be able to call a repair “fixed” because a model says so. ReplayForge records the repository and commit that an engineer authorized, retains a baseline failure and proposed patch, and is designed to require candidate, existing-suite, and clean-replay evidence before its seven deterministic gates can pass. A durable journal, signed evidence contracts, lease and consent checks, and an explicit human-review boundary make missing or contradictory evidence visible.

The current workbench supports consented source intake, persisted run status, phase and gate inspection, retained artifact previews, and an exact-diff review flow. Local PostgreSQL acceptance demonstrates the four-phase verifier using synthetic test identities. Historical fixed-fixture records separately contain remote baseline failure, candidate and clean-replay observations and a Nemotron repair. These are distinct demonstrations: the general checkout workflow has **not** completed a live trusted four-phase run, and M3 is not complete. The evaluation inventory currently has zero attempts and cannot support a benchmark success rate.

## Reproducible local demonstration commands

Current final synthetic verifier evidence is the combined v5 PostgreSQL run at
`docs/evidence/m3-azure-es256-v5-durable-acceptance-final.xml` (64 passed) and
49 focused unit tests. The older command below remains useful for the workbench
walkthrough and is not the current v5 integration test.

From the repository root, in PowerShell:

```powershell
uv sync --locked
uv run python -m scripts.check_checkout
uv run python scripts.report_m4_evaluation.py
uv run python -m scripts.test_postgres --pytest-target tests/integration/test_production_verification_loader.py --evidence-name m3-final-demo-four-phase-20261028.xml --timeout-seconds 600
uv run python -m scripts.test_postgres --web --timeout-seconds 600
```

The two PostgreSQL commands prompt for the local administrator password through
a hidden input, create random disposable database/roles, and remove them after
the tests. The first runs the four-phase signed-envelope and denial acceptance;
the second starts the local API and Next.js browser suite, including one actual
local intake/status/cancel path and synthetic UI states. Neither command calls
Nebius, runs the checkout fixture code, creates a GitHub PR, or produces live
M3 evidence.

To show the evaluation panel interactively, from the repository root run:

```powershell
Push-Location apps/web
npm run build
npm run start
```

Then open `http://127.0.0.1:3000/evaluation`. The panel is a static,
unauthenticated snapshot; it does not require the API and does not make provider
calls. Stop the server with Ctrl+C. For the fresh API-backed and browser
acceptance (which runs and exits instead of leaving a demo server up), use the
`--web` disposable PostgreSQL command above. UI quality checks are:

```powershell
Push-Location apps/web
npm run lint
npm run typecheck
Pop-Location
```
