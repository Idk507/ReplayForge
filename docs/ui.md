# UI / UX Specification

Visual direction: clean technical operations console, accessible typography, concise durable labels, no celebratory success before verifier. Navigation: Overview, New Investigation, Runs, Benchmarks, Settings. One dashboard card per run with status, repo, commit, elapsed time, stage and observed cost. Intake requires repository consent and pins a commit. Stage view renders an event timeline and evidence cards. Diff view renders file patches with line numbers, changed-path warnings and safe escaping. Verification screen separates mandatory gates from optional analyses; click each gate to see command, exact run image SHA and signed artifact. Approvals present patch hash, reviewer identity, target branch, risk summary and a clear explicit confirmation. Public judge demo supports read-only fixture browsing and safe sandbox fixture execution without open access to arbitrary repos or privileged GitHub write operations.

Client architecture: Next.js App Router, generated typed API client from OpenAPI, HTTP-only secure session cookie, CSRF token, server-enforced permissions, SSE with cursor resume, client-side exponential reconnect and duplicate-event suppression. Never trust browser-supplied verification status. Loading, empty, cancelled, failed and inconclusive states must have real copy. No color-only indicators; support keyboard use, focus and reduced motion. Performance goal: render first incident shell quickly even if inference spans minutes; stream stage events without polling huge log bodies. Sanitize code/log HTML and avoid rendering untrusted markdown as raw HTML.
